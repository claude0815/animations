3. Wie ist ein QR-Code aufgebaut?

Ein QR-Code besteht aus festen Strukturelementen und einem Datenbereich. Strukturelemente sind: die drei großen Suchmuster in den Ecken (damit der Scanner den Code findet und ausrichtet), die Trennstreifen drumherum, die Taktlinien (abwechselnd schwarz/weiß) zwischen den Suchmustern und das Dunkelmodul unten links neben dem Format-Info-Bereich.

So entstehen die Bits

Modus-ID (4 Bit): Hier 0100 für „Byte-Modus" — also beliebige 8-Bit-Bytes.

Anzahl (8 Bit): Wie viele Zeichen folgen? Bei Version 1 passt das in 8 Bit (max. 255).

Daten: Jedes Zeichen als 8-Bit-Byte (ASCII).

Endmarkierung: Bis zu vier 0-Bits zeigen das Ende der Nutzdaten.

Padding: Erst werden die restlichen Bits eines Bytes mit 0 aufgefüllt. Sind dann noch Bytes frei, kommen abwechselnd die festen Füllbytes 11101100 und 00010001.

Fehlerkorrektur: Aus den 19 Datenbytes werden 7 zusätzliche Reed-Solomon-Bytes berechnet. Damit kann der Scanner kleine Lese-Fehler selbst reparieren.

So werden die Bits platziert

Die Bits werden in einem Zickzack-Muster von unten rechts nach oben links eingetragen. Jeweils zwei Spalten werden parallel befüllt: erst die rechte, dann die linke Spalte einer Zeile. Am Ende einer Spaltengruppe dreht sich die Richtung um, und die senkrechte Taktlinie (Spalte 6) wird übersprungen.

Strukturelemente und reservierte Bereiche (z. B. Format-Info) werden dabei übersprungen — die Bits „fließen" um sie herum.

Was wäre noch nötig für einen scannbaren QR?

Echte QR-Codes wenden vor dem Drucken zusätzlich eine Maske an: ein festes Schwarz-Weiß-Muster, das per XOR über die Datenbits gelegt wird, damit keine großen einfarbigen Flächen entstehen. Außerdem werden die Format- Informationen (Fehlerkorrektur-Stufe und Masken-Nummer) an den grau markierten Stellen eingetragen.
